## ADR-001. 레이아웃 스타일의 단일 소스는 스타일시트다

**상태:** 채택 (적용 완료)

**맥락**
기존 구조는 한 속성의 최종값이 세 곳의 싸움으로 결정됐다.

1. 마크업의 인라인 `style=` (데스크톱 기본값, 약 255개)
2. `@media (min-width:721px)` + `!important` (데스크톱 보정)
3. `@media (max-width:720px)` + `!important` (모바일 재정의, 86줄에 152개)

인라인 스타일은 셀렉터 특이도로 이길 수 없으므로 미디어 블록의 모든 선언이 `!important`를 강제당했다. 이 구조에서는:

- 데스크톱을 고치려고 인라인을 수정하면 → 그 속성이 모바일에도 새어 들어가거나, 모바일 블록의 셀렉터 전제가 무너진다.
- 모바일을 고치려고 미디어 블록에 규칙을 넣으면 → `!important`를 빼먹는 순간 인라인에 져서 무효가 되고, "안 먹네" 하고 인라인을 고치면 데스크톱이 깨진다.

AI 도구가 한쪽 화면만 보고 수정하면 반드시 다른 쪽이 무너지는 구조였다.

**결정**
정적 스타일은 전부 `<style>` 시트의 클래스/데이터 속성 규칙으로 옮긴다. 마크업의 인라인 `style=`에는 **JS가 렌더마다 계산하는 동적 값만** 남긴다.

남긴 동적 인라인 19개의 목록 (이것이 전부다):

| 위치 | 동적 값 |
|---|---|
| 로고 버튼 | `background-image:{{ logoBg }}` (모바일 읽기 진행 잉크) |
| 내비 버튼 ×5 요소 | `flex:{{ n.grow }}`, `color:{{ n.fg }}`, `color:{{ n.nfg }}`, `font-weight:{{ n.w }}`, `width:{{ n.fill }}` |
| 언어 세그먼트 버튼 ×6 | `background:{{ lk.bg }};color:{{ lk.fg }}` 등 |
| 테마 아이콘 ×2 | `transform:{{ themeIcon }}` |
| 필터 버튼 | `border-color:{{ f.bc }};background:{{ f.bg }};color:{{ f.fg }}` |
| 모달 컨테이너 | `display:{{ modal }}` |
| 빈 결과 문구 | `display:{{ emptyMsg }}` |
| 타임라인 세그먼트 ×3 | `flex:0 0 calc(65.6% - 4px)` 등 (기간 비율 = 데이터) |

카드 제목의 스타일 문자열 바인딩(`style="{{ p.h3 }}"`)은 클래스 바인딩(`class="card-title {{ p.h3cls }}"`)으로 교체하고, 스크립트의 `CARD_H3`/`CARD_H3_FEATURE` 상수를 제거했다.

**결과**
- 인라인 정적 스타일이 사라졌으므로 시트의 일반 규칙이 항상 이긴다 → `!important` 전부 제거.
- 스타일을 고치려면 시트의 해당 클래스 한 곳만 보면 된다. 데스크톱 값과 모바일 값이 같은 파일 같은 이름 아래 있다.

## ADR-002. 모바일 재정의는 하단의 단일 `@media` 블록에만 둔다

**상태:** 채택 (적용 완료)

**맥락**
`!important`가 사라진 뒤에는 "무엇이 이기는가"를 결정하는 규칙이 필요하다. 특이도 경쟁으로 돌아가면 같은 문제가 재발한다.

**결정**
케스케이드 순서 하나로 통일한다.

1. **기본값 = 데스크톱.** 각 컴포넌트의 base 규칙에 데스크톱 값을 적는다. (기존의 min-width 보정 블록은 base에 흡수)
2. **모바일 재정의는 시트 하단의 `@media (max-width:720px)` 블록 하나에만** 둔다. base와 **같은 셀렉터**를 쓰면 특이도가 같으므로 뒤에 오는 미디어 블록이 자연히 이긴다.
3. 셀렉터 정책:
   - 컴포넌트 루트 = 기존 데이터 속성(`[data-bar]`, `[data-projgrid]` 등 — JS/기존 관례 유지)
   - 내부 요소 = 명시적 클래스(`.chap-title`, `.kpi-num`, `.card-blurb` 등)
   - 구조 의존 셀렉터 금지. 기존의 `[data-bar] > button:first-of-type` → `.logo-btn`, `section[data-chapter] > div:first-child > h2` → `.chap-title`, `[data-cardmeta] > span:last-child::before` → `.card-date::before`로 교체. 특히 `[data-projgrid] > article > div:last-of-type[style*="border-top"]` 같은 **인라인 스타일 문자열 매칭 셀렉터**는 이미 아무것도 매칭하지 않는 죽은 규칙이었다(대상 요소의 인라인이 먼저 사라짐) — 삭제.
   - 동종 목록 내부의 `:first-child`/`:last-child`(연락처 행, 스택 셀)만 예외로 허용.

**함께 발견해 고친 특이도 함정**
모바일에서 타임라인 라벨을 숨기던 `[data-tlbar] span{display:none}`(특이도 0,1,1)은 `!important`가 사라지면 언어 표시 규칙 `html[lang="ko"] [data-l="ko"]{display:inline}`(0,2,1)에 진다. 라벨 스팬 자체(`.tl-co`, `.tl-date`)를 숨기는 방식으로 바꿔 해결했다 — 부모가 `display:none`이면 자식의 `display:inline` 선언은 무의미하다.

**결과**
- 데스크톱 수정 = base 규칙 수정. 모바일 수정 = 하단 블록 수정. 서로를 침범할 경로가 없다.
- AI 도구에게 시트 상단 주석으로 이 규약을 명시해 두었다 (레이아웃 아키텍처 주석 블록).

## ADR-003. 반복 색상은 `:root` 토큰으로 관리한다

**상태:** 채택 (적용 완료)

**맥락**
`light-dark(#e5e4e0,#232329)` 같은 색 페어가 수십 곳에 복붙되어 있었다. 색을 바꾸려면 전체 치환이 필요했고, 미세하게 다른 유사 색(`#e5e4e0` vs `#e5e4de` vs `#e9e8e4`)이 섞여 있어 치환 실수가 잦을 구조였다.

**결정**
반복 사용되는 색 페어를 `:root`의 커스텀 프로퍼티 16개로 승격했다: `--bg` `--fg` `--ink` `--ink-fg` `--card` `--card-hover` `--card-item` `--line` `--line-soft` `--line-card` `--line-ui` `--muted` `--muted-2` `--chip-bg` `--chip-bc` `--chip-fg`. 한두 곳에서만 쓰는 색은 무리하게 토큰화하지 않고 리터럴로 남겼다.

`light-dark()`는 사용 지점의 `color-scheme`으로 평가되므로 커스텀 프로퍼티에 넣어도 라이트/다크 전환이 그대로 동작한다 (실측 확인).

**결과**
- 팔레트 변경은 `:root` 한 곳에서.
- 유사 색의 의미 구분(기본 헤어라인 vs 모달 구분선 vs 버튼 테두리)이 이름으로 드러난다.

## ADR-004. `<title>`과 부트스트랩 스크립트는 실제 `<head>`에 둔다 — 선행 ADR-003의 실제 적용

**상태:** 채택 (적용 완료)

**맥락**
선행 문서의 ADR-003은 "`<title>`을 `<helmet>` 밖 실제 `<head>`로 옮긴다"를 채택했다고 기록했지만, **본 작업 시작 시점의 파일에는 그 결정이 반영되어 있지 않았다** — `<title>`과 부트스트랩 스크립트가 `<helmet>` 안에 있었다 (선행 문서 자신이 경고한 "에디터 재저장 시 되돌림" 리스크가 실현된 것으로 추정. 같은 이유로 `siteLabel` 바인딩도 부활해 있었다).

그런데도 그 시점 파일에서 탭 제목 전환이 "동작"했던 것은 우연이었다: 브라우저/프레임워크의 파싱 타이밍에 따라 `<title>`이 helmet 관리 밖(head)에 놓이기도 하고(→ 동작), helmet의 live 엘리먼트로 잡히기도 한다(→ 매 렌더마다 `장민규`로 원복, `support.js:1487`). 실측으로 두 파일이 **동일한 소스 구조인데 서로 다른 런타임 head 구조**를 갖는 것을 확인했다. 파일 바이트 배치가 바뀔 때마다 결과가 달라질 수 있는 비결정적 구조다.

**결정**
운에 맡기지 않는다. `<title>`과 부트스트랩(테마/언어/제목 선반영) `<script>`를 문서의 **실제 `<head>`** 로 옮긴다. helmet에는 소셜 메타·폰트 링크·스타일·썸네일 템플릿만 남긴다. `theme-color` 메타 갱신은 그 메타가 helmet 소속이므로 helmet 안의 한 줄짜리 스크립트로 분리했다.

**결과**
- 언어 전환 시 탭 제목 전환(장민규 / Min-gyu Jang / チャン・ミンギュ)이 리렌더(스크롤·필터·테마)에도 유지됨을 실측 확인.
- 테마/언어 선반영이 항상 첫 페인트 전에 실행된다 (FOUC 방지 보장).
- 유지보수 규칙: **`<title>`과 부트스트랩을 다시 `<helmet>` 안으로 넣지 말 것.** 캔버스 에디터로 재저장할 경우 이 구조가 되돌아가지 않았는지 확인 필요.

## 함께 적용한 소규모 수정

| 항목 | 내용 |
|---|---|
| `{{ siteLabel }}` 미해결 바인딩 | 모달 LINK 라벨이 정의되지 않은 `siteLabel`을 참조 → `linkLabel`로 교정 (선행 문서의 "T.site 통합" 정리가 파일에서 되돌아가 있던 것) |
| 카드 배경 패치 정리 | 인라인 테두리를 CSS가 `border-color:transparent !important`로 덮던 패치-위-패치 → 클래스에 최종값(`border:1px solid transparent; background:var(--card)`)을 직접 기술 |
| 데스크톱 로고 잉크 보정 삭제 | `min-width:721px`의 `background-image:none !important` — JS(`logoBg`)가 이미 뷰포트 >720px에서 `'none'`을 반환하므로 불필요 |
| `style-hover` 속성 → CSS `:hover` | 프레임워크 전용 속성 7곳을 표준 `:hover` 규칙으로 이관 |
| 개발용 정적 서버 | Node/Python 부재 환경을 위해 PowerShell HttpListener 서버 추가 (`.claude/server.ps1` + `.claude/launch.json`, 포트 8734) |

## 검증

원본과 리팩터링본을 로컬 서버에서 나란히 실행하고, **전 요소 수치 비교**로 회귀를 검사했다.

- 방법: `main` 이하 모든 요소(전체 페이지 499개, 모달 포함 562개)의 위치·크기(rect) + 계산된 스타일 33종(display, font, color, padding, margin, gap, grid, order, overflow 등)을 DOM 경로 키로 스냅샷 → 리팩터링 후 동일 조건에서 재수집·비교
- 상태: 데스크톱(1280×800) / 모바일(375×812) × 페이지 / 모달 = 4개 상태
- 결과: **요소 추가·누락 0, 위치·크기 차이 0.** 잔여 diff는 전부 시각적 동일 사항 — ① about 문단 마진 이동(`margin:0 0 10px` → `p+p{margin-top:10px}`, rect 동일) ② 타임라인 내부 언어 스팬의 계산값 차이(부모가 `display:none`이라 렌더 결과 동일) ③ JS 런타임 상태(내비 게이지, 테마 아이콘 회전)
- 상호작용 실측: 언어 전환(본문·탭 제목·`html[lang]`), 테마 토글(`colorScheme`·`theme-color` 메타), 필터(카드 6→1→6), 모달 개폐(카드 클릭/닫기 버튼), 모바일 풀스크린 시트(sticky 헤더) 정상

## 주의사항

- 본 작업 중 다른 도구가 같은 파일을 병행 수정하는 것이 감지되었다 (00:42, 00:53 두 차례). 리팩터링은 00:53 상태를 기준으로 했고 그 이후의 외부 수정은 없음을 확인했다. **여러 AI 도구로 같은 파일을 동시에 수정하지 말 것** — 서로의 변경을 덮어쓴다.
- 리팩터링 직전 원본 백업: 세션 스크래치패드 `index.before-refactor.html` (세션 종료 시 소멸될 수 있음. git 이력이 1차 백업이다 — 현재 변경은 미커밋 상태).
