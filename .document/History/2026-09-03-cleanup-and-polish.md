## ADR-001. 필터 데이터를 끝까지 지운다

**상태:** 채택 (적용 완료 — 선행 ADR의 "데이터로 남긴다"를 뒤집음)

**맥락**
리디자인에서 필터 UI를 없애면서 `FILTERS` 상수와 `PROJECTS[].tech` 6개는 "되돌리기 어려우니" 남겨두었다. 그런데 남겨둔 결과, 읽는 코드가 하나도 없는 데이터를 **`AGENTS.md` §8 검증 3번이 계속 검사**하는 상태가 됐다. 죽은 데이터를 지키는 검증이 하나 늘어난 것이다.

**결정**
`FILTERS` · `tech` · 검증 3번 · §6 체크리스트 2번을 **한 번에** 지운다.

**근거**
- 되돌리기 비용은 git이 이미 부담하고 있다. 되살릴 일이 생기면 커밋에서 꺼내면 된다.
- 검증 명령은 살아 있는 불변식만 지켜야 한다. 죽은 데이터를 지키면 다음 사람이 그 데이터를 살아 있는 것으로 착각한다.

**결과**
- 이후 `tech`로 필터를 되살리려면 `FILTERS` 상수, `tech` 배열 6개, 필터 UI, 검증 3번을 함께 복원해야 한다.
- 같은 판정으로 `role`(6), `coFull`(6) + `CO.*Full`(2), `EDU[].badge`(5), 토큰 4개(`--line-card` `--chip-bg` `--chip-bc` `--slot`), 규칙 2개(`.nowrap` `.tag--card`)를 삭제했다. 전부 렌더 경로에 참조가 0이었다.

## ADR-002. 모달 배경은 블러가 아니라 페이지 배경색이다

**상태:** 채택 (적용 완료)

**맥락**
모달 뒤가 `backdrop-filter:blur(28px) saturate(160%)` + 반투명 스크림이었다. 뒤 내용이 비쳐 어른거리고, 배경 화면이 무엇이냐에 따라 모달 가독성이 달라졌다.

**결정**
블러와 스크림을 걷고 `background:var(--bg)` — 메인 페이지와 **같은 불투명 색**으로 칠한다. 폭도 900 → 720px로 줄인다.

**근거**
- 상세는 "덮어쓴 레이어"가 아니라 "다른 화면"이다. 뒤가 비치면 임시로 얹힌 것처럼 보인다.
- 배경이 단색이 되면 카드는 면 대비(`--card` vs `--bg`)와 테두리로만 구분된다. 그게 더 조용하다.
- 720px는 한 줄 길이를 읽기 좋은 폭으로 조인다. 스탯 카드 3열은 그대로 들어간다(200px씩).

**결과**
- `--scrim` 토큰이 죽어서 함께 삭제.
- **그림자를 다시 설계해야 했다** — ADR-003.

## ADR-003. 그림자는 접지 + 환경 2겹으로 그린다

**상태:** 채택 (적용 완료)

**맥락**
`box-shadow:0 30px 90px rgba(0,0,0,.45)` 한 겹이었다. 블러 배경일 때는 가려져 보이지 않다가, 배경을 단색으로 칠하자 **다크에서만** 얼룩진 띠로 드러났다. 거의 검은 배경(`#101011`) 위의 검은 그림자는 넓게 퍼지기만 할 뿐 카드 모서리를 만들지 못한다. 라이트에서는 같은 값이 정상적인 깊이로 읽혔다.

**결정**
```css
--shadow-1:light-dark(rgba(0,0,0,.10),rgba(0,0,0,.62));  /* 접지 */
--shadow-2:light-dark(rgba(0,0,0,.35),rgba(0,0,0,.44));  /* 환경 */
box-shadow:0 4px 10px var(--shadow-1), 0 24px 60px var(--shadow-2);
```

**근거**
- 좁고 진한 접지 그림자가 모서리를 만들고, 넓고 옅은 환경 그림자가 깊이를 준다. 한 겹짜리 넓은 블러는 어느 배경에서도 안개로만 보인다.
- 다크는 접지를 더 진하게(.62) 해야 어두운 바탕에서 대비가 산다.

**결과**
- `light-dark()`는 **색만** 받는다. offset·blur 기하는 두 테마가 공유하고 밝기만 갈린다. 테마별로 기하를 다르게 하려면 다른 장치가 필요하다.

## ADR-004. 테마 전환은 항상 버튼 중앙에서, %로 계산한다

**상태:** 채택 (적용 완료)

**맥락**
원형 확산의 시작점이 계속 어긋났다. 세 번에 걸쳐 원인이 각각 달랐다.

1. **커서 좌표 우선** — `e.clientX`를 먼저 쓰고 버튼 중앙은 폴백이었다. 키보드·자식 요소 클릭에서 좌표가 없으면 CSS 기본값 `50%`(화면 정중앙)로 떨어졌다.
2. **방향 교대** — `data-vt`가 `in`/`out`으로 번갈았다. `in`은 옛 화면이 버튼으로 **오므라드는** 연출이라, 한 번 걸러 "가장자리에서 시작"하는 것처럼 보였다.
3. **px 좌표** — `clip-path`는 `::view-transition-new(root)`의 박스를 기준으로 값을 푼다. 그 박스가 뷰포트와 1:1이 아니면 px는 어긋난다.

**결정**
- 커서 좌표를 **보지 않는다.** `data-themebtn` 훅으로 눌린 버튼을 찾아 그 중앙만 쓴다.
- 좌표와 반지름을 **%로 환산**한다. 반지름은 가장 먼 모서리까지 정확히 맞춘다.
- 방향 교대는 **유지**한다(퍼졌다가 다시 누르면 되감긴다 — 사용자가 원한 동작).
- 이징을 `linear` 340ms로. `cubic-bezier(.4,0,.2,1)`은 뒤가 납작해 마지막 40% 시간 동안 반지름이 3%밖에 안 자랐고, 그게 "끝에서 버벅"으로 보였다.

**결과**
- 검증은 `--vtx`/`--vty`를 픽셀로 역산해 버튼 중앙과 일치하는지 확인한다. **변수에 넣은 값만 보면 안 된다** — 세 번 중 두 번을 그렇게 놓쳤다.
- 브라우저 패널이 표시되지 않은 상태(`document.hidden`)에서는 View Transition이 통째로 건너뛰어진다. 이 환경에서는 애니메이션을 눈으로 확인할 수 없다.

## ADR-005. 내비 번호는 상태를 갖지 않는다

**상태:** 채택 (적용 완료)

**맥락**
`00`~`04` 번호 색이 `navState()`가 렌더마다 계산해 넣는 인라인 스타일이었다. 테마를 바꾸면 View Transition이 스냅샷을 끼워 넣는 순간 `ResizeObserver` → `onScroll` → `scrollHeight` 변화 → 재렌더가 일어나고, 그 렌더에서 `navState()`가 "아직 안 앉음" 경로로 빠져 번호가 한 번 번쩍였다.

**결정**
번호에서 활성/비활성 구분을 없애고 CSS 토큰(`--muted`) 한 줄로 고정한다. 전환 중에는 `_vtBusy` 플래그로 재측정 자체를 막는다.

**근거**
- 현재 섹션 표시는 라벨(굵기 600 + 진한 색)과 게이지 바가 이미 한다. 번호까지 같은 일을 할 필요가 없다.
- 상태가 없으면 깜빡일 것도 없다.

**결과**
- `navState()`의 `nfg` 계산이 사라져 §7 "상단 바 크롬은 JS가 색을 만든다" 예외에서 번호가 빠졌다. 라벨·세그먼트·로고는 여전히 JS 리터럴이다.
- 전체 스크롤 구간 + 테마 토글에서 번호의 인라인 스타일 변경 **0건**으로 확인했다.
